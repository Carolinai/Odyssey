## 3. 通道①：MCP 工具（11 个）

`get_task`（详情，含图片）、`query_tasks`（待办/视图列表）、`search_tasks`（关键词搜索）、`list_sprint_tasks`（迭代内任务）、`list_filter_fields` / `list_filter_views`（筛选器发现，453 个字段可搜）、`get_task_transitions` → `get_transition_form` → `submit_task_transition`（三步改状态）、`add_manhour`（登记工时）、`search_team_users`（姓名→UUID）。

**适用**：对话式查询、单条深读（描述正文+截图）、改状态。
**不适用**：批量结构化分析——输出是人读的 Markdown 行文本，无 createTime，字段稀疏。

⚠️ **已知 bug**：`query_tasks` 传 `view` 参数时用户字段被错误翻译成 `_field008_in`（多一个下划线）导致 GraphQL 400。绕开：不传 view，改传 `conditions`。

## 4. 通道②：GraphQL 直查（分析首选）

### 4.1 调用模板

```bash
CK=$(grep -o '"cookie": "[^"]*"' "$USERPROFILE/.codex/.ones-mcp.json" | cut -d'"' -f4)
curl -s -X POST "http://10.10.191.213/project/api/project/team/3HHnQbuG/items/graphql?t=group-task-data" \
  -H "Cookie: $CK" -H "Content-Type: application/json" \
  -d '{"query":"query { buckets(groupBy: {tasks: {}}) { tasks(filterGroup: [...], orderBy: {createTime: DESC}, limit: 50) { number name createTime uuid status { name category } assign { name } owner { name } priority { value } issueType { uuid } } pageInfo { count totalCount hasNextPage endCursor } } }"}'
```

### 4.2 实测可用的查询配方

**待办工单按创建时间倒序**（2026-11-02 实测：全项目 10 条）：

```json
filterGroup: [{"project_in": ["NfvccPP54SaDCYAS"], "statusCategory_in": ["to_do"], "issueType_in": ["BiGG965x", "Hkis87Tr"]}]
```

**已解决工单**：把 `statusCategory_in` 换成 `["done"]`。实测 100 条里 92 条有评论。

**分页**：`hasNextPage: true` 时把 `endCursor` 传入 `pagination: {limit: N, after: "<endCursor>"}`。

**过滤参数语法（驼峰）**：`project_in` / `statusCategory_in`（`to_do`|`in_progress`|`done`）/ `issueType_in` / `assign_in`（传用户 UUID）/ `name_match`；自定义字段加下划线：`_LMb5XC7P` 类。UI 字段 ID 映射见 `工单数据结构.md` §5。

### 4.3 解决方案/原因分析字段

```json
{ "number": 378554, "_LMb5XC7P": null, "_KQndNDDX": null }
```

- `_LMb5XC7P`（解决方案）、`_KQndNDDX`（原因分析）是**标量**，直接 SELECT，不带子选择
- ⚠️ 实测 100 条已解决工单 **0 条有值**：团队不走流转表单填写，解决方式实际写在**评论里**（走通道③）

## 5. 通道③：messages 接口（评论 + 流转历史）

```
GET http://10.10.191.213/project/api/project/team/3HHnQbuG/task/{taskUUID}/messages
```

一次返回任务全部动态流，两类消息：

| type | 内容 | 分析用途 |
|------|------|---------|
| `discussion` | 评论：`text`（纯文本）、`rich_text`（HTML）、`from`（用户UUID）、`send_time`（微秒） | **解决方式的实际载体**（92% 已解决工单有评论） |
| `system` | 字段变更：`subject_id`（操作人）、`send_time`、`ext.field_name`、`ext.old_option`/`new_option`（变更前后值） | **状态流转历史**（谁、何时、待办→已处理），时效/SLA 分析数据源 |

注意：`from`/`subject_id` 是用户 UUID，需一次 `search_team_users` 建立 UUID→姓名 缓存映射。

## 6. 踩坑记录（按发现顺序）

1. **视图查询 bug**：MCP `query_tasks` + `view` 参数 → `_field008_in` 400 错误（见 §3）
2. **命名风格三套并存**：过滤参数和 SELECT 用**驼峰**（`statusCategory_in`、`createTime`）；服务端报错里列的字段池是**下划线**风格（`create_time`），照抄必错；自定义字段 SELECT 要加 `_` 前缀
3. **`_field017` 不是通用字段**：`field017` 是 MCP 筛选层的 UI 编号，在 buckets 端点不存在，要用语义名 `statusCategory_in`
4. **时间戳是微秒**：`1793611085494130` ÷ 1e6 = Unix 秒；deadline 必须带 `(unit: ONESDATE)` 否则返回原始值
5. **「工单」有两个 UUID**（`BiGG965x`/`Hkis87Tr`，不同作用域），查全量要都带上；另有 LIMS/MES/PDR/SCADA/WMS/运维 等专用工单类型
6. **`solution` GraphQL 字段存在但恒为 null**（抽 150+ 条），别依赖它
7. **transitions REST 接口 403**：`GET .../task/{uuid}/transitions` 对非本人任务报 `PermissionDenied.TransitTasks`，流转历史改走 messages 接口
8. **无部门维度**：筛选字段池里没有「部门」，圈范围用项目 UUID 或人员 `assign_in`
9. **`transitions` 权限类 REST 接口 403 时不要重试**，换通道③

## 7. 排查技巧

- **报错即文档**：GraphQL 400 会列出当前端点的可用字段池（全量字段清单就是这么拿到的）
- **前端 bundle 挖接口**：`curl http://10.10.191.213/project/` 拿 JS 入口（`/project/scripts/index.*.js`，约 7.5MB），grep 关键词（如 `message`、`discussion`）可发现未公开接口——messages 接口即由此找到
- **GraphQL 无内省**：`__type`/`__schema` 被禁用，字段结构靠试探（一次报错只报第一个未知字段，逐个排除）

## 8. 遗留事项

- 工时明细记录（谁、何时、登记几小时）：三条通道均无，仅 `totalManhour` 累计数
- MCP 源码不在仓库（只有 dist 构建产物），如需加工具（如「批量拉取已解决工单+评论」一体化的分析工具）需从 dist 反推或找上游源码
- Cookie 有时效，过期按 §2 流程更新
