## 2. 查询模板

```graphql
query {
  buckets(groupBy: {tasks: {}}) {
    key
    tasks(
      filterGroup: [
        {
          project_in: ["NfvccPP54SaDCYAS"],
          statusCategory_in: ["to_do"],
          issueType_in: ["BiGG965x"]
        }
      ],
      orderBy: {createTime: DESC},
      limit: 10
    ) {
      number name createTime uuid
      status { name category }
      assign { name }
      owner { name }
      priority { value }
      issueType { uuid }
      deadline(unit: ONESDATE)
    }
    pageInfo { count totalCount hasNextPage startCursor endCursor }
  }
}
```

**分页**：`pageInfo.hasNextPage === true` 时，把 `endCursor` 传给下一页查询的 `pagination: {limit: N, after: "endCursor值"}`。

## 5. 过滤参数（filterGroup）语法

### 5.1 内置字段映射（UI 字段 ID → GraphQL 语义名）

| UI 字段 | GraphQL 过滤键 | 含义 |
|---------|---------------|------|
| field001 | `name` | 标题 |
| field003 | `owner` | 创建人 |
| field004 | `assign` | 负责人 |
| field005 | `status` | 状态 |
| field006 | `project` | 项目 |
| field007 | `issueType` | 类型 |
| field009 | `createTime` | 创建时间 |
| field010 | `updateTime` | 更新时间 |
| field011 | `sprint` | 迭代 |
| field012 | `priority` | 优先级 |
| field013 | `deadline` | 截止日期 |
| field015 | `number` | 编号 |
| field017 | `statusCategory` | 状态分类 |
| field040 | `solver` | 解决者 |

### 5.2 操作符后缀

`_in`（列表）、`_match`（模糊）、`_equal`（等于）等；空值类操作符传布尔值。

### 5.3 语法要点

- 过滤键格式：`{语义名}_{操作符}`，如 `assign_in: ["WoBoE1AU"]`（人员字段传 **UUID** 不是姓名）
- 自定义字段：`_{fieldNNN}_{操作符}`，如 `_field031_in: [...]`
- 语法是**驼峰式**：`statusCategory_in` ✅ / `status_category_in` ❌
- 选择字段（SELECT 子句）也是驼峰：`createTime` ✅ / `create_time` ❌
- `statusCategory` 取值：`to_do`（待办）/ `in_progress`（进行中）/ `done`（完成）

## 7. 评论与动态消息接口（2026-11-02 实测打通）

### 7.1 端点

```
GET http://10.10.191.213/project/api/project/team/3HHnQbuG/task/{taskUUID}/messages
```

返回该任务的**全部动态流**：人工评论 + 系统字段变更记录（含状态流转历史）。

### 7.2 评论消息（type = "discussion"）

```json
{
  "uuid": "xeIZX4us",
  "type": "discussion",
  "from": "7N3aN44w",              // 评论人用户 UUID
  "to": "Hjy3xoAz3Yf2ObvW",        // 所属任务 UUID
  "send_time": 1793601294737510,   // 微秒时间戳
  "text": "同步问题，已重新同步\n根本问题会在变更CC-26-016修复",  // 纯文本
  "rich_text": "<p>同步问题，已重新同步</p>...",                  // HTML 版
  "ext": { "message_status": "updated", "rich_comment_uuid": "...", "update_time": 1793601334947074 }
}
```

### 7.3 系统消息（type = "system"，即状态流转/字段变更历史）

```json
{
  "type": "system",
  "subject_id": "AxQKZC1B",        // 操作人用户 UUID
  "send_time": 1793601879091274,
  "action": "update",
  "object_attr": "field",
  "ext": {
    "field_name": "状态",
    "field_uuid": "field005",
    "old_option": { "name": "待办", "uuid": "SkzkxJro" },
    "new_option": { "name": "已废弃", "uuid": "G1PGGxSG" }
  }
}
```

→ **这补上了之前缺失的状态流转历史**（谁、何时、从什么状态改成什么），时效/SLA 分析可行了。

### 7.4 解决方式（解决方案）字段的两种读法

| 途径 | 说明 | 实测结论 |
|------|------|---------|
| GraphQL 自定义字段 | SELECT `_LMb5XC7P`（解决方案）、`_KQndNDDX`（原因分析），**标量**，直接取值 | 语法可用，但实测 100 条已解决工单中 **0 条有值**——团队不走流转表单填写 |
| messages 接口 | 评论正文 + 字段变更记录里找 `field_uuid: "LMb5XC7P"` 的 system 消息 | **主要途径**：解决方式实际写在评论里（如上例"同步问题，已重新同步…"），92% 的已解决工单有评论 |

### 7.5 用户 UUID → 姓名解析

`from`/`subject_id` 返回的是用户 UUID，需映射为姓名。可通过 MCP 的 `search_team_users` 工具，或 GraphQL 查询用户对象。同一批分析建议建一次 UUID→姓名 缓存表。

## 8. 已知限制与坑

1. **ones-tools 视图翻译 bug**：MCP 的 `query_tasks` 传 `view` 参数时，视图条件中的用户字段被翻译成 `_field008_in`（多了一个前缀下划线）导致 GraphQL 400。绕过方式：不传 view，直接传 `conditions`，或用本文档的接口直查。
2. **两套字段命名**：filterGroup 参数和 SELECT 字段都是驼峰；但服务端报错信息里列的字段池是下划线风格（`create_time`），以实际验证为准。
3. **createTime 是微秒**：`1793611085494130` ÷ 1,000,000 = Unix 秒。
4. **deadline 原始值不是日期**：必须带 `(unit: ONESDATE)` 参数。
5. **MCP 工具返回 Markdown 文本**：`get_task`/`query_tasks` 等输出是人读的文本行，不含 `createTime`；需要结构化数据（如做统计分析）时优先用本文档的 GraphQL 直查。
6. **数据边界**（更新于 2026-11-02）：~~评论内容~~、~~状态流转历史~~ 已通过 messages 接口解决（见 §7）；仍缺工时明细记录；「部门」维度无筛选字段，只能按项目/人员圈定范围。
7. **前端 JS 可挖接口**：ONES 前端 bundle（`/project/scripts/index.*.js`）里 grep API 路径是发现隐藏接口的有效手段（messages 接口即由此找到）。
8. **自定义字段两种选择语法**：`_LMb5XC7P`（UUID 直取，标量）可用；`LMb5XC7P` 不带下划线报 unknown field；`field027~field041` 是筛选池名称，**不可**用于 SELECT。
9. **「客户（QDT）」字段（2026-11-02 实测）**：自定义字段 UUID `AST3JVZw`，SELECT 写法 `_AST3JVZw { uuid value }`（必须带子字段，仅 `uuid`/`value` 有效），返回 `{"uuid":"2r2yYxcA","value":"宜昌人福"}`，`value` 即客户中文名。团队内 15458 条任务有值、70 个客户，uuid↔value 一一对应。注意区分多选字段 `Eoz4XmvC`「多选客户（QDT）」与文本字段 `5EGiPUfN`「客户名称」（工单上基本为空）。
10. **字段发现捷径（2026-11-02 发现）**：GraphQL 根级查询 `{ fields { name uuid type } }` 可一次返回全部 2332 个字段定义（含自定义字段 UUID 与中文名），比报错探池高效。另外根级 `tasks(first:100000)` 可一次拉全团队任务（filter 语法未破解，客户端过滤兜底）。

## 12. 增量同步相关

11. **⚠️ pagination 参数不生效（2026-11-03 修正）**：实测 `tasks(pagination: {limit: 500, offset: 0})` 请求 500 条实际返回全量 8644 条（`orderBy` 排序本身生效，响应单调递减）。此前记录"pagination:{limit,offset} 可用"系验证有误。影响：服务端早停无法生效，**范围过滤必须在客户端做**（拉回全量单响应后按 createTime / serverUpdateStamp 筛选）。OnesClient 已按此实现，每次增量同步实际传输全量列表（约数 MB），随后仅对变更工单拉动态流。
12. **增量水位**：`serverUpdateStamp_in` 等过滤操作符不可用，增量 = 全量列表 + 客户端 `serverUpdateStamp >= 水位-60s` 筛选。
